## Reading notes

- SECBOOT_LOCK and SECBOOTADD read 0x0 in M7 12:53/14:27, M8 19:02 and M10 19:07. Nothing wrote them; `-ob displ` shows 0 for FLASH_SECBOOTR in those core states. The secure alias still held the value: `0x50022088 = 0x0C0004B4` (M10 C9, `m10-trustzone/2026-10-09-m10-c9.txt`; also `.workspace/context/provisioning.md` from M6).
- SECWM with STRT > END means no secure area (M0 0x7-0x0, SECWM2 0x7F-0x0).
- With TZEN 0xC3 the SECWM values printed after the M4 gate (0x0-0x7F) have no effect.
- OBK (STiRoT, OEMuRoT config and data, HDPL2 rollback record) is not part of `-ob displ`; it is recorded per milestone (M4, M6, M9).
