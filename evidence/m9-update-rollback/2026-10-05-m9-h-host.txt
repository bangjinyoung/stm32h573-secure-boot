# M9 H: BL2 variants and images for the M9 board steps (host, 2026-10-05)

Firmware: commits fad474c (boot), 3d5f3d1 (app), c2bdcda (scripts). Built at c2bdcda (BUILD_ID
"c2bdcda" in both BL2 banners and the app), Release, STM32CubeCLT 1.22.0 GCC:

    cmake -S . -B build/m9-a -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi.cmake \
          -DCMAKE_BUILD_TYPE=Release -DBL2_ROLLBACK=sw
    cmake -S . -B build/m9-b ... -DBL2_ROLLBACK=hw
    scripts/make_m9_images.sh build/m9-a build/m9-b

Binaries stay in `.workspace/tmp/m9/` (not in git). ECDSA signing and the STiRoT download
encryption are randomized: a rerun gives other sha256 values and is reproduced by the
properties below. The script checks that both build trees produce the same bare_slot.bin.

## BL2 variants

| | BL2-a (build/m9-a) | BL2-b (build/m9-b) |
|---|---|---|
| CMake | BL2_ROLLBACK=sw | BL2_ROLLBACK=hw |
| MCUboot | OVERWRITE_ONLY + DOWNGRADE_PREVENTION | OVERWRITE_ONLY + HW_ROLLBACK_PROT |
| banner | `[bl2] mcuboot build=c2bdcda rollback=sw` | `... rollback=hw` |
| size (text data bss) | 46200 192 10752 | 47428 192 10752 |
| rollback record | read and log only | read, log, write on counter increase |
| interrupted OBK swap | log `interrupted flash op=` only | log, then HAL_FLASH_OB_Launch |
| HAL_FLASH_OB_Launch, HAL_FLASHEx_OBK_Swap linked | no, no | yes, yes |
| reject string | `Insufficient version in secondary slot` | `Image security counter value %u lower than monotonic value %u` |

Both: stop with `[bl2] hdpl=0x.., not started by stirot: stop` unless HDPLSR = 0x8A, log
`[bl2] rollback record state=virgin|valid|invalid|unavailable [counter0=N]` and
`[bl2] oemurot obk sha256=xxxxxxxx` (first 4 bytes of SHA-256 over OBK 0x0FFD0900-0x0FFD0B0F).
M8 BL2 (build/m8-release) for comparison: 45116 192 10680.

E8-K: no image encryption code in either BL2 (`nm` matches only the weak AES_IRQHandler and
SAES_IRQHandler vector aliases, as in M8). New log lines print record state, counters and a
4-byte hash prefix; no key bytes.

Build warnings: upstream image_validate.c:468 `%u` with uint32_t (-Wformat, only in the hw
build, where newlib uint32_t is unsigned long). Same width on this target; left as upstream.

The BL2 STiRoT counter is 0x02000000, the value imgtool `auto` derives from 2.0.0; the same as
the M8 BL2 and OEMuRoT 2.0.0, so installing BL2-a/b does not raise the STiRoT counter (D-12).
Padded images end in `10 00 2d e1 5d 29 41 0b 8d 77 67 9c 11 0f 1f 8a` (align 16 + boot
magic), the same trailer as the M3 update image that installed.
